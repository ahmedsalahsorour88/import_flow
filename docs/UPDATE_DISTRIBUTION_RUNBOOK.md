# 🚀 دليل نشر وتوزيع التحديثات وإجراءات التراجع (Update Distribution & Rollback Runbook)

> **نظام إدارة الاستيراد واللوجستيات — Sorour Logistics ERP**
> دليل مسؤولي تقنية المعلومات ومديري النظام لنشر الإصدارات الجديدة على أجهزة موظفي الشركة (6–15 جهازاً) دون انقطاع، وإدارة التوافقية والتراجع الطارئ.

---

## 🏛️ 1. الطوبولوجيا والمعمارية التشغيلية (System Topology)

يعمل النظام في بيئة المكتب وفق المعمارية التالية:
1. **الخادم المركزي (Single Server Host):**
   - جهاز السيرفر الرئيسي في المكتب يشغل خادم FastAPI على المنفذ `28080`.
   - يستضيف قاعدة البيانات التشغيلية الرئيسية (`sorour_logistics.db` بنمط SQLite WAL).
   - **الباك إند لا يُوزع على أجهزة الموظفين مطلقاً في وضع الشبكة؛ التحديث يتم على هذا السيرفر فقط.**
2. **أجهزة الموظفين (Client Workstations):**
   - من 6 إلى 15 جهاز كمبيوتر (Windows 10 / 11 64-bit).
   - تشغل تطبيق سطح المكتب المكتبي المبني بـ Flutter Desktop.
   - يتصل تطبيق كل موظف بالخادم المركزي عبر بروتوكول HTTP/REST (`http://<SERVER_IP>:28080/api/v1`).
   - ملف التثبيت والتحديثات تنزل بنقرة واحدة بدون الحاجة لصلاحيات مدير ويندوز (Non-elevated).

---

## ⚡ 2. المصدر الموحد لأرقام الإصدارات (Single Source of Truth)

للقضاء على أي تشتت أو تباين في أرقام الإصدارات، يُعتبر ملف `version.json` في جذر المشروع هو **المرجع الحاكم والوحيد** لكافة ملفات النظام.

### أداة إدارة الإصدارات (`scripts/publish_release.py`):
```bash
# فحص حالة الإصدار وتدقيق التوافق في كافة ملفات النظام:
python scripts/publish_release.py --status

# مزامنة وتوحيد كافة الملفات مع version.json تلقائياً:
python scripts/publish_release.py --sync
```

تقوم الأداة بمزامنة الملفات التالية في لحظة واحدة:
- `version.json` (المرجع الرئيسي)
- `frontend/pubspec.yaml` (إصدار حزمة فلاتر ورقم البناء)
- `installer/importflow_setup.iss` (إصدار معالج التثبيت Inno Setup واسم ملف التثبيت)
- `frontend/lib/core/constants/api_constants.dart` (`clientVersion` و `clientBuildNumber`)
- واجهات شاشة البداية والإعدادات (`HomeScreen` و `SystemSettingsDialog`)

## 📦 3. خطوات نشر تحديث جديد (How to Publish an Update)

عند الرغبة في إطلاق إصدار جديد (مثلاً `v1.0.199`):

### الخطوة 1: ترقية رقم الإصدار وتحديث ملاحظات الإصدار
```cmd
python scripts/publish_release.py --bump patch --notes "إصلاح حساب ضريبة الجدول; إضافة تنبيه التحديث التلقائي; دعم شبكة LAN"
```

### الخطوة 2: تجميع كود واجهة الفلاتر (Flutter Release Build)
```cmd
cd frontend
flutter build windows --release
cd ..
```

### الخطوة 3: بناء معالج التثبيت الذاتي (Inno Setup Installer)
باستخدام أداة Inno Setup Compiler (`ISCC.exe`):
```cmd
iscc /Q installer/importflow_setup.iss
```
سيتم توليد ملف التثبيت الجديد داخل مجلد الإصدارات:
`dist/releases/Sorour_Logistics_Setup_v1.0.199.exe`

### الخطوة 4: تفعيل الإصدار على السيرفر
يقوم السيرفر المحلي تلقائياً بخدمة ملف التثبيت عبر المسار الداخلي:
`GET /api/v1/system/download-installer`
كما يمكن نسخ الملف إلى مجلد الشبكة المشترك `\\SERVER\SorourLogistics-Updates\` كمسار احتياطي.

## 🔄 4. تجربة المستخدم في استلام التحديث (User Experience)

### الخيار الأساسي: التحديث المباشر من داخل التطبيق (Option 1 — In-App Update)
1. يفتح الموظف برنامجه اليومي كالمعتاد.
2. يقوم التطبيق عند بدء التشغيل باستدعاء:
   `GET /api/v1/system/version?client_version=1.0.198`
3. يظهر فوراً شريط أنيق أعلى الشاشة (`SystemUpdateBanner`):
   `يتوفر تحديث جديد للنظام (v1.0.199). انقر لتثبيته في ثوانٍ.`
4. ينقر الموظف على زر **"تحديث وتثبيت"**:
   - تفتح نافذة تعرض ملاحظات الإصدار وحجم الملف (~198 MB).
   - يضغط **"بدء التنزيل والتثبيت"** فيبدأ شريط التحميل السريع مباشرة عبر شبكة المكتب المحلية بسرعة تفوق 20-50 ميجابايت/ثانية (يستغرق التحميل أقل من 5 ثوانٍ محلياً!).
   - عند اكتمال التحميل، يضغط الموظف **"تثبيت الآن وإعادة التشغيل"**، فيقوم النظام بإغلاق الواجهة الحالية وتشغيل المثبت الصامت `/SILENT /NORESTART` وإعادة فتح البرنامج بالإصدار الجديد.

### الخيار الاحتياطي: التثبيت اليدوي عبر المجلد المشترك (Option 2 — Network Share Fallback)
إذا تعذر التنزيل على جهاز معين (مثلاً بسبب حظر جدار حماية محلي على ذلك الجهاز):
1. يفتح الموظف متصفح ملفات ويندوز ويكتب: `\\SERVER\SorourLogistics-Updates`
2. ينقر نقراً مزدوجاً على `Sorour_Logistics_Setup_v1.0.199.exe` ويضغط **Next -> Install**.
3. يكتمل التحديث دون فقدان أي إعدادات سابقة.

## 🛡️ 5. حماية التوافقية ومنع تعارض الإصدارات (Client-Server Compatibility Guard)

لحماية البيانات التشغيلية من أي عبث ناتج عن استخدام إصدار قديم جداً:
- يرسل تطبيق العميل ترويسة `X-Client-Version: 1.0.198` في كل طلب HTTP.
- يتضمن `version.json` حقلاً اسمه `min_compatible_version` (مثلاً `1.0.180`).
- **حالة التحديث العادي (`client_version < latest_version`):**
  - شريط تنبيهي أصفر غير مزعج مع إمكانية إغلاقه ومواصلة العمل.
- **حالة عدم التوافق الإلزامي (`client_version < min_compatible_version`):**
  - شريط تنبيه أحمر عاجل + منع الإغلاق المؤقت:
    `تنبيه إلزامي: إصدار التطبيق الحالي غير متوافق مع قاعدة البيانات. يرجى التحديث للمتابعة بأمان.`

## ⏪ 6. إجراءات التراجع الفوري عند الطوارئ (Emergency Rollback Protocol)

في حال تم نشر إصدار واكتشف موظف وجود عطل يعيق العمل في ذلك الإصدار:

### 1. تراجع أجهزة الموظفين إلى الإصدار السابق:
يشغل مسؤول الـ IT الأمر التالي على السيرفر في ثانية واحدة:
```cmd
python scripts/publish_release.py --rollback-to 1.0.198
```
يقوم السيرفر فوراً بضبط الإصدار المستهدف على `1.0.198`. عند فتح أجهزة الموظفين، يظهر لهم تنبيه التراجع لتثبيت الإصدار السابق المستقر.

### 2. تراجع قاعدة البيانات (Database Point-In-Time Rollback):
إذا تضمن التحديث تعديلاً على جداول قاعدة البيانات قبل التراجع، يتم استرجاع النسخة الاحتياطية الآمنة التي أخذها النظام تلقائياً قبل الترقية عبر:
```cmd
python scripts/restore_database.py --backup backups/daily_backup_YYYYMMDD_HHMMSS.db
```
ثم إعادة تشغيل خدمة الباك إند:
```cmd
python scripts/service_manager.py restart
```
ويمارس الموظفون عملهم الطبيعي فوراً.
