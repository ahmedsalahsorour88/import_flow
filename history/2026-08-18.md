### 📁 Files Changed

### 📊 Technical Changes

- Resolved single-point stacking bottleneck by replacing single-column stacking with 3D candidate point grid tiling across pallet/item top surfaces.

- Enabled 2.5D visual elevation rendering in `ContainerLoadPlanPainter` with offset shading so stacked items step up visually in Top View.

## 📝 [2026-08-18 12:38] - Completed Task: 90-Degree Automatic Pallet Rotation & Explicit Failure Reason Reporting

### 📌 Overview

- **Task Code:** BP-022 / FE-022
- **Description:** Enhanced the CBM packing algorithm in `ContainerRequirementEngine` to support automatic 90-degree horizontal rotation (swapping Length & Width). If a pallet's entered Width exceeds container width (e.g. `220 L x 350 W cm`), but swapping Length and Width allows it to fit (e.g. `350 L x 220 W cm`), the system automatically evaluates both orientations and packs the cargo. When both dimensions exceed container max width (e.g. `250 L x 250 W cm`), the engine rejects packing and reports an explicit Arabic failure reason explaining the exact dimensional constraint violation.

### 📁 Files Changed

- `frontend/lib/core/utils/container_requirement_engine.dart`:
  - Added `failureReason` string field to `ContainerPackingResult`.
  - Updated `packCargo` initial dimension check: evaluates both normal (`fitsNormal`) and rotated (`fitsRotated`) orientations before rejecting items.
  - Generates detailed, user-friendly Arabic failure messages when items exceed container max width, length, height, or payload weight.
- `frontend/lib/features/cbm_calculator/screens/cbm_calculator_screen.dart`:
  - Updated Visual Load Planner table and red alert box to display `res.failureReason` directly.

  - Added unit tests for 90-degree pallet auto-rotation (`350x220` vs `220x350`) and explicit failure reason validation for `250x250` oversized cargo.
